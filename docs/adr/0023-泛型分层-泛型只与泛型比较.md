# ADR 0023 —— 泛型分层：泛型只与泛型比较

- 状态：已采纳（调整 [ADR-0022](./0022-泛型在约束上界实例化显示.md) 的跨层比较行为）
- 日期：2026-07-28

## 背景 Context

ADR-0022 让泛型以「约束上界处的规范代表」入图后，代表与具体类型在同一平面比较：`C1<T extends string> = T` 与预设 `string` 被判等价合并，`C2<T> = T` 被分类为 universe 画布框。用户指出这在数学上混淆了两个宇宙：具体类型是**值集合**（集合宇宙 P(V) 中的元素），泛型是**从集合到集合的函数**（带定义域约束的类型构造器，函数空间中的元素）——函数与集合之间没有典范的相等关系，「在上界求值」只是一个投影（求值同态），投影的像不等于函数本身

## 决策 Decision

实体按「具体 / 泛型」分为两层（stratum），IR 增加 `TypeEntity.parametric` 标记（可选，缺省为具体；语言无关概念，Rust / Golang 泛型同样适用）：

1. **跨层一律 `unrelated`**：泛型实体与任何具体实体（代码导出、virtual 预设）之间不做 checker 比较，直接判不相关 —— 图上各自独立
2. **泛型不参与 special 分类**：`C2<T> = T` 不再因代表为 `unknown` 成为 universe 框，`G<T> = T & never` 不再成为 ∅；泛型实体恒为普通矩形，标签上的参数声明就是「这是族」的标识
3. **层内比较不变**：泛型与泛型之间仍按上界代表比较（ADR-0022 语义），`C1<T extends string>` ⊂ `C2<T>` 照常嵌套；两个同域同体的泛型仍判等价（同一个函数）
4. **投影由用户显式表达**：想看「族的代表落在具体平面的哪里」，写一个非泛型别名即可（`type HandlerBound = Handler<unknown>`）—— 工具不再替用户悄悄投影

## 代价与后果 Consequences

- ADR-0022 中「BoxLit ⊆ BoxStr<T extends string>」这类跨层嵌套不再出现；示例代码里 `Handler<X>` 与 StrHandler / WideHandler 的逆变链断开，Handler<X> 成为独立集合。族与其实例之间的真实关系是「求值 / 隶属」而非子集，画成子集本就是投影带来的混淆 —— 断开是修正不是损失，需要该对比时用显式别名重建
- 层内代表比较的语义边界（协变精确、逆变翻转、不变不可概括）沿 ADR-0022 不变

## 备选方案 Alternatives

- 维持同平面比较（0022 现状）—— 否决：函数与集合判等价在数学上不成立，教学工具不能示范这种混淆
- 给泛型层画独立的视觉样式（虚线边等）—— 推迟：标签中的参数声明已足够标识；分层本身先落地
- 层内改为「族的逐点序」（domain ⊆ + ∀T 逐点比较，经泛型签名探针）—— 推迟：协变体下与代表比较结论一致，收益集中在混合变性场景，探针工程量大，等真实需求
